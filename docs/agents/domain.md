# Domain Documentation

Chirawn is a single-context repository.

Before significant work, agents should read:

1. `CONTEXT.md` at the repository root.
2. Relevant ADRs under `docs/adr/`, if present.
3. The actual code in the area being changed.

Use the canonical terms defined in `CONTEXT.md` in specifications, tickets, tests, and review findings. Do not introduce synonymous names casually.

Create `docs/adr/` only when recording a decision that is hard to reverse, non-obvious without context, and selected from a real trade-off. Keep ADRs short.
